# BGM・SEのユーザー体験点検

対象: 0.9.2.87 / 2026-11-20

コード、現行MP3の数値測定、Chromiumの再生ノードを点検した。実機での試聴済みという意味ではない。

## 見つかった問題と変更

| 問題 | 対応 |
| --- | --- |
| フィールド曲・タイトル曲の末尾に長い低音量区間 | フィールドは末尾4秒、タイトルは5.1秒をループ対象から除外。音源の微小な残響を含む測定であり、完全な無音の長さとは区別する |
| トレーナー戦の初回開始位置が繰り返しに反映されない | WebAudioのloopStart/loopEndへ開始位置を適用 |
| 勝利曲などの音量差 | 原チャンネル数で測定したRMSに基づくテーマ別gain。波形の強弱は維持 |
| 道具獲得時に直前の勝利曲へ戻る | 結果画面へvictory/safari/mapの種別を付ける |
| 結果・ガイド・技未使用確認で曲が止まる | 操作に不要な停止を除外 |
| media代替とWebAudioの同時再生、遅い再生要求の競合 | 要求番号を照合し、成功した新方式へ切替時に旧方式を停止 |
| 曲が届かず遭遇準備で待ち続ける | 準備待ち1.5秒、取得8秒上限。新曲準備までは前曲を維持 |
| 切替・停止・波形端のクリック | 短いgainフェード、デコード済みループ端4msをゼロへ寄せる |
| サファリ捕獲に激しい戦闘曲 | 穏やかなwaterテーマを捕獲結果まで維持 |
| タワーに速いアジト曲 | 遅い短調のcaveテーマへ。専用曲の新規制作ではない |
| タイトル鳴き声が大きい、SE開始が急 | 鳴き声gain0.6、ノイズSEの立ち上がり3ms |
| AudioContextのinterrupted状態 | suspendedと同様に次の操作・復帰でresumeを試行 |

## 自動確認

`tests/audio-experience-browser.cjs`をPlaywright/Chromiumで実行。音声デバイスから聞いた評価ではなく、実再生ノード・再生位置・場面・音量・JSエラーを検査する。

- フィールドのループ範囲、ガイド中の継続、野生戦→勝利、次の道具獲得での古い勝利曲抑止。
- トレーナー登場→戦闘→2体目まで戦闘曲継続→最終勝利。
- サファリの穏やかな曲と捕獲結果までの維持、ミュート/復帰。
- デコード失敗→media→キャッシュ済みWebAudioへ切替後、二重BGMなし。
- SE連打時の発音数上限40、SE音量0、blur時のサイコロ連続音停止。
- 非表示/復帰イベント模擬でBGM/SE停止・BGM復帰。実OSバックグラウンド検証ではない。
- タイトル末尾スキップ、実際の開始ボタンによるマップ曲への接続。
- 遅い取得でもprepareScene待機が上限内、JSエラーなし。

## 残る確認

iPhone Safari/Android Chrome実機で、スピーカー/イヤホン、消音・着信・画面ロックからの復帰、ループの音楽的なつながり、SEの耳障りさ、属性攻撃と獲得演出との主観的な一致をベータテストで確認する。HTML media代替のループ端はtimeupdate依存で、WebAudioのようなサンプル単位の精度はない。低速時は前曲を維持するため場面との一時的な不一致があり得る。

この作業は既存の「戦闘進行中に画面非表示で敗北」のルールを変更していない。その扱いは別の残タスク。
