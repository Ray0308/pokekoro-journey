# 現行チュートリアル：研究所の模擬戦（0.9.2.91）

2026-11-21。ユーザーの「内容や見せ方が不自然」という指摘と「研究所の模擬戦」の選択に基づく。

- 選んだ御三家とゴンベ、相手は博士のピカチュウ。同じ編成/相手/ゲージを継続。
- 時間を止めて同じ属性を3つ以上なぞる→スタートから実時間10秒でパワーをためる→満タンの仲間を押して技を使う。
- ゴンベの「たくわえる」は次の10秒で強化された正の通常攻撃を試してから終了。ゲージ不足なら追加の10秒を遊べる。
- 模擬戦に撃破の必要はない。HPゲージを置かず、今回のパワー/ダメージと実ゲージを表示。反撃と強制ひんしは行わない。
- 選択御三家の複合タイプを含む実属性で6×5盤面を作る。消去列だけ重力で補充。ルートは固定3マスに限定しない。計算と技は本編の共有関数。
- 初回の必須から比較用交代/ひんし/使えない技操作/強制並べ替えを外す。本編の相性・ひんし・任意編成の表示は維持する。
- 模擬戦後に博士がピカチュウを譲る→ボール操作→図鑑/3匹/一度だけの初期報酬→御三家を先頭に本物のサイコロで出発。

保存はopening.mockBattle。安定したtrace/ready/doneと盤面・実ゲージ・強化・実ダメージを保存する。10秒途中や技演出途中の中断では直前の安定地点から再開。主データの所持・在庫・通常戦へ練習状態を混ぜない。

新規version 5。未完了v4のchosen/borrow/practiceは新方式へ移行、旧の実践課題の途中値は再利用せず、新しい模擬戦の冒頭へ。名前/報酬/所持は保持。完了済みはやり直さない。v1/2/3と、v4の練習以後の段階は旧ルートを保持。

編集元: mock-practice-rules.js / mock-practice.js / practice.css、会話と接続はopening-config.js / opening.js / opening-rules.js。検査はtests/mock-practice.cjs / tests/mock-practice-browser.cjs。3御三家、3画面寸法、10秒と実タッチ、保存/中断、技、譲渡/投球/図鑑/サイコロまで確認。実機の体感・最終承認は別。

## 目的と保護範囲

説明閲覧では完了させず、消去・技発動・反撃・編成・サイコロの実操作成功を条件に進める。既存のゴンベ遭遇、承認済み博士会話、主人公名、御三家選択、ニドラン♂貸与の会話、ピカチュウ確定捕獲、図鑑授与、初期報酬は維持する。

通常の戦闘ルール・技データ・相性・マップ抽選・在庫は変更しない。練習は専用dialog・専用モデルで動かし、`BattleTurnRules`、`PokemonSkillRules`、`partyTypePower`、`puzzleCharge`、`pokemonTypeMultiplier`、`drawTypeGem` を再利用する。敵や技の原作効果を別に実装しない。

## UI・失敗・停止

- 練習の文章は盤面外。1段階1操作。3マスは金枠と順序番号、ボタン・仲間は金枠で強調。
- 10秒課題以外は時間を進めない。対象外の盤面・ボタンは処理しない。通常のルールを変えず、成功可能な専用盤面を保証する。
- なぞり失敗は短い再挑戦メッセージ。盤面を壊さず、やり直せる。10秒課題で消せなければスタートから再挑戦。
- タッチはPointer Eventsと `touch-action:none`、マウスも同じ経路判定。説明を盤面へ重ねない。
- 練習中にタブ非表示となった10秒ラウンドは、練習開始待機へ戻す。通常戦の敗北処理へ送らない。完全な途中秒数の復元はしない。
- 編成・サイコロは本編UIを使い、練習中は関係しないクリック・pointerdown・決定キーを捕捉。イベントハンドラー後に実状態を再検証する。誤タップやEscapeで学習画面を離れない。
- サイコロの着地通知は通常時に追加の待機を作らない。初回練習時だけ成功表示のPromiseを返し、約1.1秒後に通常の着地イベントへ進む。

## 保存・互換性

既存 `opening.stage` を利用。戦闘練習は `stage='practice'` と `opening.practiceStep`、編成／サイコロは `partyLesson/diceLesson`。独立したゲーム進行セーブは作らない。

初期報酬受け取り後に `partyLesson` へ進む。`pokedexReceived` と完了ガードで再読込・再確定の二重報酬を防ぐ。貸与ポケモン・練習HP・ひんし・盤面を `state.owned/party` へ書き込まない。名前保存方式は変更しない。

再読込後は成功済みチェックポイントから、その課題のモデルを再構成する。途中の指の経路・10秒残時間・成功演出は保存しない。技解放後の段階では検証済みのゲージ、ひんし後の段階では固定対象のひんしを再構成する。練習の途中で在庫や通常戦に影響しない。

旧version 1／2は従来の初回経路・練習のまま。完了済みやデバッグには新課題を強制しない。version 3/4が体験型の課題を通る。
