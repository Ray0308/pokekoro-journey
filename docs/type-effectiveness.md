# 属性パズルのタイプ相性

## 判定

現在の18タイプの通常の相性表を使う。
攻撃側は消したピースの属性、防御側は相手ポケモンの主・副属性。
複合タイプは倍率を掛け合わせ、0・0.25・0.5・1・2・4倍になる。
無効は他方の弱点より優先する。例: でんき→じめん・ひこうは0倍。

タイプ一致ボーナス・技ごとの例外・特性・テラスタルは追加しない。
既存の主副属性別のパーティー火力、コンボ、属性数ボーナスの式も変更しない。
`puzzleCharge`へ相性倍率を渡し、丸めは従来どおり最後に一度だけ行う。
旧内部呼び出しの真偽値も受け付けるが、通常のバトルは数値倍率を使う。

サファリのなかよしパワーには常に1倍を使う。
属性ボールの一致判定や捕獲率、トレーナーのHP・時間・編成・報酬は変更しない。

## 出典と生成

PokéAPIの `type_efficacy.csv` と `type_names.csv` を固定コミットから取得した。
元のスナップショットは `data/type-efficacy.source.csv` と `data/type-names.source.csv`。
取得URL・コミット・SHA-256は `data/type-chart-source.json` に記録する。
配布元のライセンス全文は [pokeapi-data.txt](licenses/pokeapi-data.txt) を参照。

```sh
npm run types:generate
npm run types:check
npm test
```

APIのタイプ番号をゲームへ直接コピーせず、日本語名でゲームの属性順へ変換する。
全324通りの欠損・重複・倍率・名前を検査し、`type-chart.generated.js`を生成する。
生成に通信は不要。元CSVを更新する場合は取得元とハッシュも記録し直す。
プレイ中にAPIを呼ばない。

## 表示

バトル開始時は現在のパーティーで最も相性のよい属性を案内する。
どの属性も無効なら、撤退して編成を変えるよう案内する。
消した時の表示も、効果抜群・いまひとつ・無効の判定と一致させる。
無効でもピースは消えてコンボは続くが、パワーは加算せず、パワーの飛翔演出も出さない。

## 検査

`tests/type-effectiveness.cjs`で全324通りをAPI番号との独立した対応表で照合する。
全1025種の複合判定、4倍・1/4倍・無効、現行の鋼とフェアリーの相性、実パワー、
サファリの等倍、元データ欠損の拒否も確認する。
ブラウザでは実際の3ピース入力、パワー・表示の一致、小画面の案内、撤退を確認する。
