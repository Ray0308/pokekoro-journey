# 設計判断・合意事項

更新日: 2026-11-18。現行仕様は [SPECIFICATION.md](SPECIFICATION.md)、進捗は [DEVELOPMENT_STATUS.md](DEVELOPMENT_STATUS.md)。

この記録は、採用した判断と撤回・変更した案を区別して残す。単なる提案を実装済みの合意へ変えない。詳細な変更単位は [CHANGELOG.md](../CHANGELOG.md) を参照する。

| 判断                 | 採用内容                                                           | 理由・背景                                                                                                     |
| -------------------- | ------------------------------------------------------------------ | -------------------------------------------------------------------------------------------------------------- |
| 対象と雰囲気         | 子供向け。相棒はゴンベ。初代カントーの雰囲気を基調に全世代を混ぜる | 汎用的で安っぽいパズル表現を避け、ポケモンと冒険する体験を重視する                                             |
| 体験を妨げない演出   | SE、消去、溜めて攻撃する演出を残し、盤面上の大型文字と揺れを廃止   | 実際にブロックが見えず操作できなくなる指摘があった。派手さより視認性を優先する                                 |
| 音声の開始           | 最初にタップを促し、その操作でメニューとBGMを開始                  | モバイルの音声制約と、無反応・無音のタイトル体験を両立して解消する                                             |
| BGMの継続            | 操作を契機に即時切替し、準備中は前曲を維持する                     | 戦闘開始・勝利時の不自然な無音が繰り返し指摘された                                                             |
| 現行盤面             | 0.9.2.45から6列×5段・30マス。内部420×350                           | 盤面の拡大だけで敵表示を圧迫せず、参考のパズドラ画面に近い上下の配分と正方形ブロックを両立する                 |
| 待機表示             | 色が透ける9pxのぼかし＋薄い白、中央スタート                        | 初期の強い白重ねはベタ塗りに見えたため0.9.2.47で修正。開始前と操作中を区別しつつ盤面を読ませすぎない           |
| カウントダウン       | 濃い緑の文字と明るい下地。出始めから不透明                         | 白い盤面で白文字が読めず、短いGOにフェードインが不向きだったため                                               |
| 技の入口             | 待機中の仲間タップで任意表示。敵交代を先に済ませる                 | 自動で開く大きな技画面が不評で、倒れた敵に攻撃技を使えない構造も問題になった                                   |
| 戦闘の失敗           | 10秒で削り切れなければ反撃でランダムな1匹がひんし                  | 失敗体験と編成・技の意味を加える。長時間の単調な1パズルを避ける                                                |
| ターン上限           | 最大6ターン案を撤回し、生存条件だけで継続                          | 最大6匹という結果と、固定ターン数は別。防御・復活で継続でき、3匹なら常に3ターンという仕様でもない              |
| ひんし属性           | 盤面から除かず、通常どおり消せる                                   | 消せないブロックで詰むことを防ぐ。生存仲間がいない属性のダメージ/ゲージだけ0にする                             |
| 戦闘状態の場所       | ひんし・ゲージ等を戦闘内に置き、通常セーブの所持/編成は変えない    | 戦闘をまたいだ意図しないひんしや、連戦中の状態消失を防ぐ                                                       |
| 個別技               | 各種1つの代表技、攻撃・強化・防御・盤面・支援・復活へ本作用に変換  | 原作の全技仕様をそのまま持ち込まず、パズルの合間に判断できるスキル体験にする                                   |
| 種族値               | 火力・敵耐久・ゲージ速度へ反映。味方個別HPは追加しない             | 取得済みデータを個性へつなぎ、現在の反撃ひんしルールを維持する                                                 |
| トレーナー抽選       | 職業/場所/進行度別。初回ボスは専用固定データ                       | 野生共通抽選では「そのトレーナーらしい手持ち」にならなかった                                                   |
| 編成内の重複         | 全体方針として禁止。原案の重複枠を別種へ変更                       | ユーザーが重複を面白くないと明示。原作の完全再現より本作の体験を優先した                                       |
| 一般候補の御三家     | 原則除外、ニャオハだけ明示的に許可                                 | ユーザーの例外指定を保持する                                                                                   |
| ライバルの系統       | 自分の系統と抽選済み編成を保存。ゴンベへの有利判定はしない         | 主人公の相棒はゴンベであり、初期提案の有利御三家選択は採用しなかった。後の初回御三家選択を理由に自動変更しない |
| データ取得           | PokéAPIの固定版を一括取得・生成してローカルで使う                  | プレイ中の通信待ち、サービス状態、表記の変化に依存せず、再現・検査できるようにする                             |
| IDと表記             | 全国図鑑No.で結合し、日本語名・タイプは参照データと照合            | 名前の改行、バンギラスの副タイプ等の誤りを訂正し、文字列一致の事故を防ぐ                                       |
| 技と生成物           | 設定JSONを編集し、生成JSは再生成する                               | 1025種の割当と能力・UI・テストの整合性を保つ                                                                   |
| 本作のガンテツボール | 原作の個別ボールとは別に18属性の一致捕獲ボールとして扱う           | 余剰ボールの使い道とタイプを選ぶ楽しさを加えるため                                                             |
| 初回案内             | ゴンベ→研究所→御三家→貸与練習→ピカチュウ→図鑑                      | 最初から無説明で3匹を持たせる状態を改善し、捕獲と仲間の導入を体験させる                                        |
| 初回と旧保存         | 初回進行を保存し、既存プレイヤーへは強制しない                     | これまでの手持ち・ボール・マップ進行を失わないため                                                             |
| データ削除           | 確認後にゲーム進行だけ消し、音量等を維持                           | 最初からやり直す入口を作り、誤操作と設定の巻き添えを防ぐ                                                       |
| マップの差し替え     | 画像比率と元画像を保持し、通路に専用座標を置く                     | 狭い場所への詰め込みや、背景と経路の不一致を避ける                                                             |
| 道の補助点           | routeViaは描画専用。イベントのマス数は15のまま                     | 迷路の角を曲がるためにマスやサイコロ進行を増やさない                                                           |
| 素材と難易度         | 素材対応時にHP・レベル・報酬の調整を混ぜない                       | ユーザーが細かな調整は後でまとめると指定。差分の原因を追いやすくする                                           |
| 引き継ぎの保存先     | docs/の3資料とルートAGENTS.md                                      | 当初のObsidianへの記録希望を、ユーザーがこのリポジトリ内への保存に具体化した                                   |

## 判断上の補足

- 図鑑データ・画像の取得元ライセンスと、ポケモンそのものの権利は区別する。出典とライセンス資料は `docs/licenses/` およびデータのsource/manifestに保持する。「個人利用だから権利上の確認がすべて不要」と本資料では断定しない。
- 初期の30秒通常戦闘、6×6盤面、最大6ターン、番号だけの未登録画像等は過去の段階の記録であり、現在の仕様として復活させない。
- 開発履歴は全会話の逐語録ではない。ユーザーの指示・実装・公開の証拠を残し、採用しなかった案や未検証の内容を確定仕様へ混ぜない。
